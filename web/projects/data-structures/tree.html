Data Structures

Trees

A tree is a non-linear data structure based on a graph. Trees are a type of directed non-weighted graph, which is hierarchal and upholds certain properties.

Nodes in a tree have a hierarchy, or depth. They may have children, with a greater depth than themselves, and every node except the root has exactly one parent, which has a smaller depth, and there are no edges between sibling nodes, which have the same depth as each other.

The root node (naturally at the top of the tree...) has a depth of 0, and is the only node with no parent. Leaf nodes are nodes which have no children, though they are not necessarily at the very bottom of the tree.

Trees are used for the directory structure of file storage, where folders contain other folders that contain files. A similar approach is used for the HTML DOM, where an element's children are contained within the tags.

Trees are also used to improve time complexity of algorithms. Generally, for a tree of n nodes, the maximum depth of the tree is approximately log(n), and is never greater than n. By writing algorithms to operate on trees, the worst case scenario is often related to the depth of the tree, giving the algorithm a worst case time complexity of O(log n), which is considered faster than O(n) on average.

Binary Search Trees

Some trees must also follow certain rules, known as tree properties. They are similar to axioms in mathematics.

A binary search tree is a tree that follows these rules:

  • Every node has at most two children
  • One of the child nodes has a smaller value than the parent node, and the other has a greater value than the parent

Binary search trees can be used to perform binary search, which is usually faster than linear search. It starts at the root node and compares the value of the node with the target. Then, if it is greater than the target, it will look at the smaller child, and if it is less than the target it will compare with the larger child. This continues until the target is found, or a leaf node is reached with no match.

Heaps

Another type of tree is a heap. In order to be a heap:

  • The tree is complete - every row except for the last must be full
  • Every node has at most two children
  • In a min heap, every node's value must be less than the smaller of its children (this is known as the heap property)
  • In a max heap, every node's value must be greater than the larger of its children (heap property)

Heaps are commonly used as priority queues. When items are enqueued, they are given a priority and added to the bottom of the tree. Then, the item sifted up, swapping with its parent until the max heap property is satisfied, placing it as far into the queue as it belongs.

For dequeueing, the root node is removed since it necessarily has the highest priority, and is replaced by the item at the bottom. Then, it is sifted down, swapping with the greater of its two children until the heap property is once again upheld, preparing the tree for another dequeueing.

Huffman Trees

A Huffman tree is similar to a max heap, and is used for lossless compression known as Huffman Encoding:

  • Every node has at most two children
  • The frequency of a node is equal to the sum of the frequencies of its children
  • Every node with an associated character is a leaf node (has no children)

Huffman trees are also classed as "tries", since the paths through the tree spell out codewords in binary.

Huffman trees are powerful because since every character is a leaf node, there is no ambiguity. If the binary path ends on a character, you know that it must be that character, and not a combination of others.

Huffman trees also make use of the priority queue feature of heaps, placing more frequent letters higher up the tree, so they have a shorter codeword length.
